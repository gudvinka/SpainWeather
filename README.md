# SpainWeather — погода в Испании

Личный проект для выбора города для переезда: каждый запуск сохраняет кадр веб-камеры, замер метеостанции и небо/воздух
для **Овьедо** и **Гранады**, а потом собирает из этого сайт — по дням, месяцам и городам.

Стек: TypeScript + Playwright, Node 24 (запускает `.ts` напрямую, без сборки).

## Как запускать

Команды выполняются в терминале VS Code (Ctrl+\`) в папке проекта.

| Команда | Что делает |
|---|---|
| `npm.cmd run snap` | **основная**: кадры камер, данные станций и Open-Meteo по обоим городам и другим местам, пересборка сайта |
| `node src/snap.ts gijon enol` | то же, но только для указанных городов/мест (`id` из `cities.ts`) — например, первый кадр новой камеры |
| `npm.cmd run report` | только пересобрать страницы из уже собранных данных (после правок дизайна) |
| `npm.cmd run check` | проверка типов (`tsc`) + все тесты |
| `npm.cmd test` | только тесты |

`npm.cmd` вместо `npm` — из-за запрета скриптов в PowerShell. Если выполнить один раз
`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`, будет работать и просто `npm`.

Смотреть результат: на компе — открыть **`index.html`** в корне (перекинет на `site/index.html`);
отовсюду — **https://gudvinka.github.io/SpainWeather/**.

Терминал: подходит и PowerShell, и обычная командная строка (cmd). В cmd вместо PowerShell-команд вроде
`Add-Content` — свои (`echo строка>> файл`), git и npm работают одинаково.

Установка с нуля (на новом компе): `npm install`, затем `npx playwright install chromium`.

### Что пишет запуск

```
OK    oviedo станция -> 21.3°, роса 19°, влажность 87%, дождь сегодня 0 мм
WARN  granada камера: кадр камеры старый: 95 мин
ERROR granada станция: UGR Albayzín недоступна: HTTP 503
...
Итог: Овьедо — OK · Гранада — ошибок 1, предупреждений 1
```
- `OK` — источник отработал;
- `WARN` — данные подозрительные: используются, но день помечается «⚠ данные под вопросом»;
- `ERROR` — данные невозможные или источник недоступен: в расчёт не идут. Код выхода 1, если были ошибки.

Один упавший источник не мешает остальным.

## Автозапуск (GitHub Actions) и сайт

**Сайт:** https://gudvinka.github.io/SpainWeather/ — GitHub Pages из ветки `main`, обновляется сам после каждого
коммита (в Actions это запуски «pages build and deployment»). Сайт публичный, как и репозиторий.

Репозиторий: https://github.com/gudvinka/SpainWeather. Файл `.github/workflows/snap.yml` запускает `src/snap.ts`
на серверах GitHub. Новые данные бот `github-actions[bot]` сам коммитит в `main`.

**Кто запускает: Cloudflare Worker** `spainweather-cron` (код — `cloudflare/worker.js`, там же как настроить).
Он нажимает «Run workflow» через API GitHub по расписанию `0 9,13,16 * * *` (UTC): зимой это **10:00 / 14:00 / 17:00**
по Мадриду, летом — **11:00 / 15:00 / 18:00**; вечером светло круглый год (в декабре закат в Овьедо около 17:55).
Своего расписания у `snap.yml` нет: расписание GitHub (`schedule`) опаздывало на часы или пропускало запуски,
а вместе с Cloudflare давало по 6 сборов в день, часть ночью.

- Токен GitHub для Worker'а — fine-grained, только SpainWeather, право Actions: Read and write, **срок — год**
  (до октября 2027). Хранится в Cloudflare как **Secret** `GITHUB_TOKEN` (Worker → Settings → Variables and Secrets).
  Когда истечёт, запуски перестанут появляться в Actions: выпустить новый и заменить секрет.
- Адрес `workers.dev` у Worker'а выключен (вкладка Domains): он не нужен, расписание работает без него.
- **Поменять время:** Cron Triggers в Cloudflare (Worker → Settings → Trigger Events). Код Worker'а из репозитория
  сам не обновляется — после правки `cloudflare/worker.js` вставить его в панели Cloudflare (Edit code → Deploy).
  **После Deploy проверить Overview → Triggers = 1:** при правке кода в редакторе расписание слетало.
- **Работает ли будильник:**
  - проще всего — в **Actions**: три запуска **snap** в день с пометкой **Manually run**;
  - в **Cloudflare**: Worker `spainweather-cron` → вкладка **Observability** → период **Last 24 hours** → в поиске
    `snap-dispatched` (или в панели полей выбрать **action** = `snap-dispatched`). На каждый запуск — строка со
    временем и `status: 204` (GitHub принял запуск). Если GitHub отказал — строка-ошибка с его ответом
    (401 — токен истёк или неверный). Пусто — будильник не звонил: проверить Triggers.
- **Запустить вручную:** вкладка **Actions** → **snap** → **Run workflow** (всегда берёт свежий код из `main`;
  кнопка Re-run повторяет старый запуск на старом коде).
- **Посмотреть результат:** вкладка **Actions** → нужный запуск → шаг «Собрать данные» — там те же строки `OK` / `WARN` / `ERROR`.
  Все запуски (от Cloudflare и от кнопки) помечены **Manually run**.
- **Красный запуск** = был `ERROR` (источник недоступен или данные невозможные). Open-Meteo при сбое
  (таймаут 20 с, ошибка сервера) пробуется второй раз через 10 с; `ERROR` — только если не ответил дважды. Всё, что удалось собрать, всё равно сохранено.
- Проверено 12.10.2026: с серверов GitHub работают все источники, включая видеокамеру rtsp.me.

### Git: две копии проекта

На GitHub и на компе — две отдельные копии, сами они не синхронизируются:
- **забрать** данные бота к себе — `git pull` (VS Code: Source Control → `…` → Pull);
- **отправить** свои изменения — `git add -A`, `git commit -m "..."`, `git push`;
- кнопка синхронизации внизу VS Code делает pull, затем push.

**Перед своими правками — всегда `git pull`**: бот коммитит 3 раза в день, иначе свой push будет отклонён.

## Сайт: три уровня страниц и раздел «Таймлапс», два языка

Названия используем везде — в разговоре, в README и в коде (`src/report.ts`).
Наверху каждой страницы «хлебные крошки» `SpainWeather › Овьедо › октябрь 2026` — по ним можно подняться на любой уровень,
в правом верхнем углу — переключатель **RU | ES**: ведёт на ту же страницу на другом языке.

| Уровень | Название | Файл (`<язык>` = `ru` или `es`) | Что на странице | Функция |
|---|---|---|---|---|
| 1 | **SpainWeather** | `site/<язык>/index.html` | главная: карточка на каждый город — фон в цвет сегодняшнего дня, сейчас °, мин/макс, осадки, «ощущается», рисунок знакового места (собор / Альгамбра); последней — карточка **«Таймлапс»** (фон — свежий кадр, сначала камеры других мест) | `buildSpainWeather` |
| 2 | **City overview** | `site/<язык>/<город>/index.html` | обзор города: годы → карточки месяцев (полоска дней по цветам, дни без данных — пустая рамка; средние мин/макс, счётчики дней по типам, осадки, отопление) | `buildCityOverview` |
| 3 | **Month details** | `site/<язык>/<город>/<ГГГГ-ММ>/index.html` | детали месяца: шапка «этот месяц / обычно», легенда цветов, строка на каждый день — карточка погоды + кадры камеры | `buildMonthDetails` |
| — | **Timelapse** (каталог) | `site/<язык>/timelapse/index.html` | группы «Наши города» и «Другие места»; карточка камеры — последний кадр, ▶, температура, «источник · с какого дня · сколько кадров» | `buildTimelapseCatalog` |
| — | **Timelapse** (камера) | `site/<язык>/timelapse/<камера>/index.html` | все кадры камеры подряд (до трёх в день): кадр, дата, время, **температура в момент кадра**, тип дня; ползунок поверх полоски, где у каждого кадра кусочек цвета его дня, отметки начала месяцев; кнопки «кадр назад / показ / кадр вперёд», скорость 2× / 5× / 10× (кадров в секунду); ← → и пробел на клавиатуре; внизу — чья камера и откуда погода | `buildCameraTimelapse` |

Переходы: SpainWeather → клик по городу → City overview → клик по месяцу → Month details.
Таймлапсы: SpainWeather → карточка «Таймлапс» → каталог → камера. С City overview — круглый значок **▶** рядом с
заголовком, сразу на таймлапс основной (первой) камеры города (есть, если у города есть кадры).

### Timelapse
- Страница пересобирается при каждом сборе вместе с остальными, так что новые кадры появляются в ней сами;
  открывается на последнем кадре.
- Тип дня под кадром — итог за весь день (как цвет дня), а кадр — один момент, поэтому они могут не совпадать.
- Рамка кадра — по его пропорциям (у Валенсии 4:3, у остальных 16:9).
- У камеры-плеера Овьедо (`rtspEmbed`) на кадрах до 10.11.2026 внизу панель плеера RTSP.ME — при показе низ обрезается
  у всех кадров этой камеры (и у новых, чистых), чтобы рамка не прыгала; файлы не трогаются.
- У каждой камеры свой таймлапс; адрес — по имени камеры (`name` в `cities.ts`, уникальное на весь сайт — тест).
  Название в каталоге — город или место, а у города с несколькими камерами ещё и `title` камеры («Гранада · Альгамбра»).
- **Температура под кадром:** у города — замер станции того же сбора (время совпадает, допуск 15 мин); если замера нет
  или он с ошибкой — модель Open-Meteo за этот час (`temps` в `sky.json`). У других мест — всегда модель.
- **Другие места** (`PLACES` в `cities.ts`) — камеры вне сравнения городов, только для таймлапса (список — в «Источниках»). Без станции и без страниц погоды; цвет дня и температура — по модели
  Open-Meteo (итоги дня — мин/макс из температур по часам, осадки модели). Их сбои — предупреждения, не ошибки.
- Старые адреса `site/<язык>/<город>/timelapse/…` (до раздела) — перенаправления на страницы камер.
- **Month details** с несколькими камерами: кадры дня — строкой на камеру, над строкой подпись камеры белой плашкой.
- Список кадров вшит в страницу (у дня подпись/цвет/тип, у кадра — номер дня, время, путь); скрипт `TIMELAPSE_JS`
  заранее подгружает 10 следующих кадров.

### Телефон
Отдельной мобильной версии нет — те же страницы, правила в `@media (max-width: 600px)` в `report.ts` (проверено на
ширине iPhone 17 Pro Max — 440 точек). На компьютере всё как раньше. На телефоне:
- везде поля по краям уже, карточки (городов, месяцев) на всю ширину;
- **City overview** — без полоски дней по цветам, счётчики дней в две колонки;
- **Month details** — шапка: заголовок в строку, плитки по две в ряд; **легенды цветов нет**. Дни — список
  коротких белых карточек в рамке цвета дня (строки в две колонки, небо — отдельной строкой внизу). Кадры скрыты:
  нажатие на день раскрывает их во всю ширину («кадры ▾» / «скрыть ▴»), это маленький скрипт `DAY_TOGGLE`.
- **Month details** везде (и на компьютере): у текущего месяца над днями справа белая кнопка **«сегодня ↓»** —
  плавно к сегодняшнему дню (у каждого дня якорь `#dДД`, например `…/2026-10/index.html#d13`); после прокрутки вниз
  справа внизу появляется белая круглая кнопка **«↑»** — наверх.
- На телефоне в шапке месяца нет и строки об источниках («Обычно» — среднее за …).
- **Timelapse** — та же раскладка, номер кадра отдельной строкой; карточки каталога и «Таймлапс» на главной — во всю ширину.
- Проверять так же скриншотом Playwright с `viewport: { width: 440, height: 956 }`, `isMobile: true`; смотреть, чтобы
  ширина страницы (`document.documentElement.scrollWidth`) была 440 — иначе что-то вылезает вбок.

### Шапка Month details

Вывод одной фразой («Октябрь пока: по температуре как обычно, дождей как обычно»; при < 7 днях данных — «пока мало
данных») и строка плиток «этот месяц» / «обычно»:

| Плитка | Как считается | Города |
|---|---|---|
| днём в среднем | среднее дневных максимумов | оба |
| дождливые дни | осадки за сутки ≥ 1 мм | оба |
| серые дни (без солнца) | без дождя, облачность днём ≥ 60 % (облачно / пасмурно / туман); облачность — низкие и средние облака, без перистых | оба |
| пекло (35°+) | максимум ≥ 35° | Гранада (`showHeat` в `cities.ts`) |
| плохой воздух | европейский индекс за день > 60 | оба |
| световой день | восход–закат 1-го числа | оба |

«Обычно» — среднее за тот же месяц **4 прошлых лет** (для октября 2026 — октябри 2022–2025; в 2027 окно сдвинется)
из архива Open-Meteo (модель, без ключа). Хранится в `site/<город>/history.json`, каждый месяц качается один раз.
Пороги общие для наших дней и архива — константы `RAINY_MM`, `GREY_CLOUD`, `HEAT`, `BAD_AIR` в `src/days.ts`.
Часы солнца не используем: модель их сильно завышает.

Цвет дня — по ощущению: **тёплое — солнце, серое — серо, синее — мокро**. Солнечно (жёлтый) · переменная облачность
(светло-жёлтый: белые облачка, солнце выглядывает) · облачно (почти белый: светлые облака, обычный день) · пасмурно
(свинцово-серый) · туман (молочный) · морось · дождь · ливень (от голубого к тёмно-синему). Палитра — `KIND_STYLE`
в `src/days.ts`. Порядок важности: осадки → туман (если днём не прояснилось) → небо.

Цвет считается **по дождю днём, 9–21 ч**: ночной дождь цвет не меняет (в подписи он остаётся — «дождь ночью»).
Сколько выпало — по станции, когда — по модели Open-Meteo (дождь по часам в `sky.json`). Если ≥80 % дождя пришлось на ночь — цвет по небу («дождь ночью»), если на день —
по всей сумме («дождь днём»), иначе — сумма станции × доля дневного дождя. Если модель дождя почти не видела (<0.5 мм) или записи старые — цвет по всей сумме.
Цвет сегодняшнего дня предварительный (Open-Meteo — только прошедшие часы); окончательный — после первого сбора
на следующий день, когда приходят итоги станции за вчера и Open-Meteo пересчитывает прошлые дни.

## Где лежат данные

Всё по городам и месяцам: `site/<город>/<ГГГГ-ММ>/`. У других мест (`PLACES`) — так же, `site/<место>/<ГГГГ-ММ>/`, но
только `screenshots/`, `sky.json` и `log.jsonl`.

| Файл | Что внутри | Откуда |
|---|---|---|
| `screenshots/*.jpg` | кадры камер — правило для всех камер: ширина 1080px (ширина вертикального ролика), JPEG 75, ~40–70 КБ; если камера отдаёт меньше — сохраняется оригинал, без растяжения; у камеры-плеера кадр берётся прямо из видео (у Овьедо поток 2304×1536), поэтому тоже 1080; до 10.11.2026 — 960px, имя `2026-10-12_17-27_<камера>.jpg` — по имени камеры кадры разных камер города не смешиваются | камеры |
| `weather.jsonl` | замер станции на каждый запуск (одна строка JSON), с исходными данными `raw` и замечаниями `issues` | станция |
| `daily.json` | итоги дня: мин, макс, дождь (только Овьедо — 31 день назад); у дней с запасной станции ещё `sun` (часы солнца) и `source` | станция |
| `sky.json` | облачность, часы солнца, индекс воздуха, восход/закат, дождь по модели (`rain` за сутки, `rainDay` — 9–21 ч), температура по часам `temps` (0…23, с 10.11.2026) по дням | Open-Meteo |
| `../history.json` | (одна на город, `site/<город>/history.json`) итоги того же месяца прошлых лет для «обычно» | архив Open-Meteo |
| `log.jsonl` | замечания запуска: старый кадр, недоступный источник, несходящаяся сверка | проверки |
| `index.html` | перенаправление на страницу месяца в `site/ru/…` (сами страницы — в `site/ru/`, `site/es/`) | — |

Храним только сырые данные; итоги дня и месяца считаются заново при каждой сборке страниц — поэтому правила
можно менять задним числом, и вся история пересчитается.

Станция Овьедо перезаливает файлы раз в несколько минут, и в этот момент `clientraw.txt` бывает пустым — тогда сбор
повторяет запрос через 8 секунд. Если файл пустой и со второго раза, значит, станция перестала отправлять данные: в
журнале будет «станция отдала пустой файл, файл не обновлялся с …» (время берётся из заголовка `Last-Modified`).

**Запасная станция.** Если основная станция города не ответила, сбор берёт замер с запасной (`backup` в `cities.ts`) и
пишет в журнал предупреждение (не ошибку — данные дня есть); в замере тогда есть поле `station` с id запасной. Для
Овьедо это AEMET OpenData: замер раз в час с опозданием около часа (поэтому «отстаёт» для неё — от 2,5 ч), в ответе
только последние 12 часов. Дождь и мин/макс «с полуночи» склеиваются из часов этого ответа и сохранённых прошлыми
сборами за день (`raw`); если часов с утра не хватает — день помечается «⚠ данные под вопросом». Счётчиков «за месяц /
за год» у AEMET нет.

**Пустые дни в `daily.json`.** Каждый сбор смотрит последние 10 дней: если у дня нет итогов (основная станция
молчала), берёт итоги дня запасной станции (у AEMET — мин, макс, дождь и часы солнца за полные сутки, публикуются с
опозданием дня на 3; пока их нет — день ждёт следующего сбора). Итоги основной станции за дни, когда она стояла
(сбор был, а нормального её замера — ни одного), не берутся: после простоя `clientrawdaily.txt` отдаёт за эти дни нули
или мусор. Нужен бесплатный ключ (https://opendata.aemet.es/centrodedescargas/altaUsuario):
на GitHub — секрет `AEMET_API_KEY`, локально — переменная окружения с тем же именем. Без ключа запасная просто не
сработает (ошибка в журнале), остальное собирается как обычно.

Других ключей не нужно.

## Правила карточки дня (кратко)

- **мин · макс** — за сутки (Овьедо — итоги станции; Гранада — последний замер дня)
- **осадки** за сутки — те же слова, что у цвета: <0.2 мм без осадков · <1 покапало · 1–5 морось · 5–15 дождь ·
  >15 ливень (по сумме за сутки, не по силе дождя). Плюс «днём / ночью» — если ≥80 % дождя пришлось на 9–21 ч или
  на ночь (по модели); «весь день» — если по замерам станции капало между всеми замерами; иначе — без уточнения
- **ощущение** по замеру около 14:00: от 18° — по точке росы (сухо · комфортно · нормально · влажно · душно · гнетуще), ниже 18° — по разнице температуры и точки росы (сухо · сыро · сыро и зябко)
- **небо** по облачности днём: <20% ясно · <60% переменная · <90% облачно · иначе пасмурно. Облачность — только
  **низкие и средние** облака (`max(low, mid)` из Open-Meteo): высокие тонкие перистые не считаем, солнце светит сквозь
  них и день ощущается солнечным (для Гранады это частый случай)
- **туман** — утром температура почти равна точке росы
- **воздух** по европейскому индексу: 😊 до 40 · 😐 до 60 · ☹ выше
- **отопление** по средней за сутки: <12 нужно · <15 вечером

## Агенты

Агент — это Claude, который работает без чата: его запускает событие, он выполняет задание по своей инструкции
с заранее выданными правами и оставляет результат (issue, комментарий, пул-реквест). Устроено так же, как в командах:

| Что | Где | Зачем |
|---|---|---|
| Правила проекта | `CLAUDE.md` (в git) | читают все: и Claude в чате, и агенты на GitHub |
| Личные заметки | `CLAUDE.local.md` (не в git) | только у владельца на компе |
| Описание агента | `.claude/agents/<имя>.md` | роль, что проверять, как отчитываться, что нельзя; в шапке — инструменты и модель |
| Общие разрешения | `.claude/settings.json` (в git) | что можно без спроса (`gh issue …`, `npm run check`…) |
| Личные разрешения | `.claude/settings.local.json` (не в git) | свои настройки на компе |
| Триггер и запуск | `.github/workflows/<имя>.yml` | когда запускать, какие права GitHub дать, какие запреты добавить |
| Доступ к Claude | Secret `CLAUDE_CODE_OAUTH_TOKEN` | токен подписки (`claude setup-token`); в коде его нет |

### Разрешения и запреты
- **Инструкция** (`CLAUDE.md`, файл агента) — просьба текстом: агент старается её соблюдать. **Настройка**
  (`.claude/settings.json`) — жёсткое правило: его проверяет сама программа Claude Code и просто не даёт сделать
  запрещённое.
- Где лежат: `.claude/settings.json` — в git, для всех (люди, агенты); `.claude/settings.local.json` — личный, не в git.
- Файл — строгий JSON: **комментариев нет** (`//` — ошибка), лишняя запятая в конце списка — тоже ошибка.
- `allow` — можно без спроса; `deny` — нельзя никогда. Запрет сильнее разрешения. Запреты действуют всегда,
  разрешения из `settings.json` в безлюдном запуске на «недоверенной» папке не применяются (поэтому у сторожа они
  передаются в `watchdog.yml` через `--allowedTools`).
- Запись правила: `Инструмент(что)`:
  - `Read(./.env)` — не читать файл; `Read(./dist/**)` — не читать ничего в папке `dist`; `Read(./**/*.key)` — не
    читать файлы `.key` где угодно;
  - `Edit(./src/**)` — не править файлы в `src`;
  - `Bash(npm run check)` — ровно эта команда; `Bash(gh issue *)` — команда с любым продолжением.
- Сейчас в `deny` — образцы на будущее: пароли и ключи (`.env`, `*.pem`, `*.key`) и папки сборки (`dist`, `build`).
  В проекте их нет, поэтому они ничего не ограничивают, но если такие файлы появятся — агенты их не прочитают.
  Чтобы закрыть свою папку, добавить в `deny` строку `"Read(./папка/**)"`.

### Сторож (`watchdog`)
- **Когда:** сразу после каждого сбора `snap` (`workflow_run`); вечером раз в день по своему расписанию
  (`schedule`, 21:30 Мадрид летом / 20:30 зимой — не зависит от Cloudflare и snap); кнопка Actions → **watchdog** →
  **Run workflow**. Кто разбудил — передаётся агенту, от этого зависит проверка.
- **Что проверяет** (результат сбора, сам источники не опрашивает) — по каждому городу за последний сбор:
  кадр камеры есть и не пустой (≥ ~5 КБ); замер станции есть, не `stale`, без ошибок (у Овьедо ещё вчерашний день в
  дневнике `daily.json`); небо и воздух Open-Meteo за сегодня и вчера; ошибки в `log.jsonl`; запуск `snap` зелёный.
  При первом сборе дня — что вчера было 3 сбора; вечером — сколько сборов было сегодня.
  Штатный сбор считается с **14.10.2026** — более ранние (тестовые) дни сторож не проверяет.
- **Итог — один из трёх уровней** (первая строка ответа; по ней ставится пометка в Actions):

  | Уровень | Когда | В Actions | Issue / письмо |
  |---|---|---|---|
  | `Watchdog: OK` | всё в порядке | зелёный запуск, без пометок | нет |
  | `Watchdog: ВНИМАНИЕ — …` | разовый сбой источника; пропущен один-два сбора за день; snap красный один раз | зелёный + жёлтая ⚠ | нет |
  | `Watchdog: ПРОБЛЕМА — …, issue #N` | тот же сбой 2 сбора подряд; snap красный 2 раза подряд; за день ни одного сбора или нет кадров/замеров больше суток; пропуски сборов 2 дня подряд | зелёный + красная ❌ | issue (или комментарий в открытом) → письмо |

  Красный **запуск** значит только «сломался сам сторож» (лимиты, токен) — об этом тоже приходит письмо.
  Отчёт целиком — на странице запуска (Summary) и в шаге «Сторож проверяет сбор».
  **Починилось** — комментарий «Восстановилось … Можно закрыть» в открытом issue; закрывает человек.
- **Долгий простой основной станции** (у города с запасной — Овьедо): если последний замер основной станции (без поля
  `station` в `weather.jsonl`) старше 3 суток — один раз отдельный issue «Watchdog: основная станция <город> не работает
  с ДД.ММ» (в этот запуск — ПРОБЛЕМА), дальше, пока он открыт, — только ВНИМАНИЕ без новых комментариев; станция
  ожила — один комментарий «снова отвечает, можно закрыть». Issue проблем сбора («Watchdog: проблемы сбора ДД.ММ») —
  отдельный, «восстановилось» после разовых сбоев пишется только в него.
- **Разбор причины:** при сбое сам заходит на страницу камеры (hispacams, meteo365), станции (meteobuenavista, UGR),
  Open-Meteo — только эти адреса разрешены (`WebFetch(domain:…)`).
- **Что нельзя:** менять файлы, коммитить, пушить, запускать workflow, закрывать issue. Права GitHub у запуска — только
  чтение репозитория и запусков + запись issue; у самого агента — только чтение файлов, команды и адреса из
  `--allowedTools` в `watchdog.yml`; плюс явные запреты `--disallowedTools`. Всё, что не разрешено, в безлюдном запуске
  (`--permission-prompts none`) отклоняется.
- **Поменять задание:** править `.claude/agents/watchdog.md` (обычный текст), закоммитить — следующий запуск пойдёт по новой.
- **Токен:** в cmd `claude setup-token` → скопировать → GitHub → Settings → Secrets and variables → Actions →
  New repository secret `CLAUDE_CODE_OAUTH_TOKEN`. Расходует лимиты подписки владельца.
- **Попробовать локально** (в папке проекта, Claude Code уже залогинен): `claude -p "Проверь сбор" --agent watchdog`.
