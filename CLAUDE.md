# SpainWeather — правила проекта для Claude и других агентов

Этот файл читают Claude Code и агенты (в том числе на GitHub Actions) в начале каждой сессии. Здесь — правила
проекта: что где лежит, как проверять, чего нельзя. Подробное устройство — в `README.md`.
Личные заметки владельца — в `CLAUDE.local.md` (не в git).

## Что это
Сайт со статистикой реальной погоды по дням в Овьедо и Гранаде: кадры камер, данные метеостанций, небо и воздух
из Open-Meteo. Метрики формулируются «для жизни»: солнце или пасмурно, сыро или нет, дождливые дни, нужно ли отопление.
TypeScript без лишних зависимостей (Playwright, sharp).

## Страницы (так их называем)
- **SpainWeather** — главная `site/<язык>/index.html`, карточки городов (`buildSpainWeather`, `renderCityCard`).
- **City overview** — `site/<язык>/<город>/index.html`, карточки месяцев (`buildCityOverview`, `renderMonthCard`).
- **Month details** — `site/<язык>/<город>/<ГГГГ-ММ>/index.html`, шапка месяца + строки дней (`buildMonthDetails`,
  `renderMonthHeader`).
- На каждой странице «хлебные крошки» SpainWeather › Город › месяц (`crumbs()`).
- Два языка: `site/ru/…` и `site/es/…`, переключатель RU | ES (`langSwitch()`), тексты в `src/i18n.ts`. Новый текст
  на странице — всегда через словарь в обоих языках (тест сверяет ключи). Испанский — черновой.
- Данные и кадры — в `site/<город>/<ГГГГ-ММ>/`, общие для языков; старые `site/<город>/…/index.html` и корневой
  `index.html` — перенаправления на `site/ru/…`.
- Телефон: правила в `@media (max-width: 600px)` в `src/report.ts` (раздел «Телефон» в README). Любую правку
  страниц проверять **и на компьютере, и на телефоне** (Playwright, viewport 440×956, `isMobile: true`; ширина
  страницы `document.documentElement.scrollWidth` должна быть 440).

## Договорённости по коду
- Node 24 запускает `.ts` напрямую; `erasableSyntaxOnly` — никаких enum, namespace, параметров-свойств в конструкторе.
- Храним только сырые данные (+ `raw` + замечания `issues`); итоги считаются при сборке страниц.
- Проверки качества в `quality.ts`: `error` — значение не используется, `warn` — используется, но день помечается
  «⚠ данные под вопросом». Падение одного источника не должно ронять остальные.
- После изменений: `npm run check` (tsc + тесты); для страниц — скриншот Playwright и посмотреть глазами.
- Время везде местное (Испания, CET/CEST). На GitHub Actions задано `TZ: Europe/Madrid` — не убирать, иначе даты и
  проверка «станция отстаёт» поедут.
- Кадры камер уменьшаются `sharp` до 960px, JPEG 75 (~25–60 КБ).
- Макеты и временные файлы — только в `tmp/` (в .gitignore).
- **README держим актуальным.** Заметное изменение (новая возможность, страница, источник данных, настройка,
  разрешения, агент, автозапуск) — в том же коммите коротко описать в `README.md`, **как это теперь работает**.
  README — описание текущего устройства, а не журнал изменений: устаревшее исправлять или удалять, не дописывать
  «раньше было так». Отдельный файл изменений (CHANGELOG) не ведём — историю хранит git.
  Если меняются правила проекта — обновить и этот файл.

## Сбор данных и GitHub
- Репозиторий https://github.com/gudvinka/SpainWeather (публичный), единственная ветка `main`.
  Сайт — GitHub Pages из `main`: https://gudvinka.github.io/SpainWeather/
- Workflow `snap.yml`: `npm ci` → playwright → `npm run check` → `node src/snap.ts` (continue-on-error) → бот
  коммитит `site/` и `index.html` → запуск красный, если были ERROR.
- Запускает сбор **Cloudflare Worker** `spainweather-cron` (код `cloudflare/worker.js`, cron `0 9,13,16 * * *` UTC =
  Мадрид зимой 10/14/17, летом 11/15/18). Cron всегда по UTC; летнее время в Испании — до последнего воскресенья
  октября. Своего расписания (`schedule`) у `snap.yml` нет — не добавлять: GitHub опаздывал и давал лишние сборы.
- В коммитах — только noreply-почта владельца (`49454475+gudvinka@users.noreply.github.com`) или бота;
  npm registry — только `registry.npmjs.org` (файл `.npmrc`). Никаких других адресов почты и зеркал.

## Что важно помнить о данных
- Станция Овьедо (`clientraw.txt`): поля 4 темп., 5 влажн., 7/8/9 дождь день/месяц/год, 46/47 макс/мин, 72 точка росы.
  `clientrawdaily.txt`: блоки по 31 (макс, мин, дождь), последний — вчера.
- Поле 11 clientraw («Max Rain Rate») — единицы неясны, поэтому «ливень» по интенсивности не сделан; `raw` хранится.
- Станция Гранады UGR — HTML в Latin-1; если вёрстка поменяется, `parseUgr` бросит понятную ошибку; тест на
  `fixtures/ugr-index.htm`.
- Журнал замечаний сбора — `site/<город>/<ГГГГ-ММ>/log.jsonl` (камера, недоступный источник, сверки).
- Часы солнца из Open-Meteo — модель, похоже, щедрая; для отдельного дня кадр камеры честнее.

## Правила для агентов
- Отвечать и писать отчёты по-русски, просто, без жаргона.
- **Не пушить в `main`** и не делать force-push. Изменения кода — только отдельной веткой и пул-реквестом.
- Не править данные в `site/<город>/…` руками — их пишет только сбор (`src/snap.ts`).
- Перед любым пул-реквестом — `npm run check` зелёный.
- Не создавать дубликаты: перед новым issue проверить, нет ли уже открытого на ту же тему, и дописать в него.
- Агенты проекта описаны в `.claude/agents/` (сейчас — `watchdog`, сторож сбора данных; запускается `.github/workflows/watchdog.yml`).
